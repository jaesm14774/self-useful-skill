## 打開系統看：哪些部分撐起這條路徑？

### 系統邊界和責任圖（讀者需要看懂範圍時才保留）

先依[架構總覽指南](../references/architecture-overview.md)定義範圍、主路徑和必要支線。總覽要在靜止畫面交代範圍內的完整責任，不逐一列出程式模組；保留重要資料、非同步及信任關係，刪除系統中不存在的選用節點及其箭頭。以下是可改寫的 Mermaid 起手式；圖上連線必須以程式碼儲存庫的證據為準。

```mermaid
flowchart LR
  caller[使用者／呼叫端]
  upstream[上游來源（若適用）]
  downstream[外部服務／下游消費者（若適用）]
  subgraph boundary[本系統邊界]
    entry[入口／觸發]
    core[主要處理]
    store[(主要持久狀態)]
    queue[[佇列／事件匯流排（若適用）]]
    worker[非同步工作者（若適用）]
  end
  caller -->|呼叫／要求| entry
  upstream -->|資料／事件（若適用）| entry
  entry --> core
  core -->|讀寫| store
  core -.->|發布工作（若適用）| queue
  queue -.->|非同步交接| worker
  core -->|同步交付（若適用）| downstream
  worker -->|外部副作用（若適用）| downstream
```

**這張圖回答：** [這條情境有哪些部分一起完成結果？哪些責任在系統外？]

**如何讀這張圖：** [先帶讀者看主要路徑，再說明重要支線和責任邊界，最後連到對應入口。]

**證據／未確認事項：** [主要節點、連線、資料路徑和邊界的證據；未確認事項要明確標示。]
